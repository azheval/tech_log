# techlog-stat v2

`techlog-stat` чытае тэхналагічны журнал 1С і стварае аўтаномныя справаздачы. У другой версіі з'явіліся адзіны аналіз `analyze` за адзін праход і параўнанне перыядаў `compare`.

## Архітэктура

```text
прыдатныя файлы
  -> патокавы parser internal/techlog
  -> упарадкаваны апрацоўшчык падзей
       -> агульныя агрэгаты і часавыя bucket
       -> SQL/SDBL fingerprint
       -> трасы CALL/SCALL і кантэкст памылак
       -> агрэгаты і samples блакіровак
       -> web, жыццевыя цыклы, працэсы, ліцэнзіі і файлавая база
  -> text / CSV / JSON / аўтаномны HTML
```

Файлы могуць разбірацца паралельна праз `--workers`, але stateful-аналізатары атрымліваюць падзеі ў парадку discovery. Фільтр прымяняецца да падзеі перад усімі калектарамі, таму totals, SQL, трасы і блакіроўкі адносяцца да адной выбаркі.

Parser і калектары працуюць за адзін праход. Разбор файлаў можа ісці паралельна, але ўпарадкаваны апрацоўшчык атрымлівае абмежаваныя batch і захоўвае дэтэрмінавую stateful-карэляцыю. Прыклады для расследавання, стан трас, чакаючыя кантэксты памылак і HTML-preview абмежаваны.

## Пакрыцце падзей і кансерватыўная карэляцыя

Акрамя overview, SQL, блакіровак і трас CALL, `analyze` фарміруе асобныя раздзелы:

| Падзеі | Аналіз |
| --- | --- |
| `SCALL` | Серверныя выклікі па `Interface`, `IName`, `Method`, кантэксце, карыстальніку, базе і працэсе; працягласці, даступныя рэсурсныя метрыкі і абмежаваныя павольныя прыклады. |
| `VRSREQUEST`, `VRSRESPONSE`, `VRSCACHE` | Web-запыты/адказы, нармалізаваны URI, статус/вынік, байты, cache hit/miss і абмежаваныя павольныя/памылковыя прыклады. Адказ або cache-падзея звязваецца толькі з адзіным сумяшчальным кандыдатам у lane source/process/thread без канфлікту ідэнтыфікатараў. |
| `SESN`, `CONN` | Толькі яўныя пары start/open і finish/close з яўным ID. Attach-падобныя запісы і запісы без ID не ствараюць меркаваны жыццевы цыкл. |
| `PROC`, `SCOM` | Агрэгаты працэсу і SCOM, абмежаваныя павольныя PROC-прыклады і толькі яўна распазнаныя SCOM-сувязі працэсаў. |
| `LIC`, `HASP` | Класы атрымання/вяртання/памылак ліцэнзіі, крыніца HASP і бяспечная зводка АС. У прыкладах рэдагуюцца шляхі ліцэнзій, серыйныя значэнні і MAC-адрасы. |
| `EXCPCNTX`, `EXCP`, `QERR` | Групы памылак і абмежаваныя зыходныя памылкі/кантэксты. `EXCPCNTX` узбагачае толькі адну бліжэйшую сумяшчальную памылку ў акне карэляцыі; неадназначныя і несупастаўленыя кантэксты застаюцца ў метрыках якасці. |
| `DBV8DBEng` | Агрэгаты файлавай базы па функцыі, табліцы, катэгорыі, файле, базе, працэсе, карыстальніку і кансерватыўным класе аперацыі. `Rows` і `RowsAffected` адрозніваюць адсутнасць і нуль; абсалютныя шляхі файлаў рэдагуюцца. |

Нармалізацыя URI выдаляе значэнні query, сартуе імены параметраў і замяняе лікавыя або UUID-падобныя сегменты шляху. Гэта робіць групы больш устойлівымі і змяншае выпадковае раскрыцце даных, але не з'яуляецца мяжой бяспекі для адвольнай raw-падзеі.

## Лакальны web-інтэрфейс: `serve`

Запусціце ўбудаваны лакальны frontend з дазволеным root журналаў:

```powershell
./techlog-stat.exe serve --input C:/v8/logs --listen 127.0.0.1:8080
```

Frontend аўтаномны, убудаваны ў выканальны файл і не выкарыстоўвае CDN або знешнія assets. Гэты frontend запускае аналіз, паказвае status і progress і дазваляе запытаць адмену. Для запуску выбіраюць каталог толькі ў межах root `--input` і glob адносна гэтага каталога, а таксама параметры аналізу і фільтры.

Укладкі «Агляд», «Падзеі», SQL, «Трасы», «Блакіроўкі» і «Зыходныя» падтрымліваюць фільтрацыю і drill-down да зыходных падзей. Drill-down паўторна чытае толькі нязменны набор файлаў, matched дадзеным запускам, і ніколі не выкарыстоўвае шлях або glob ад браўзера. UI параўноўвае любыя два завершаныя in-memory запускі і фарміруе downloads CSV, JSON і аўтаномнага HTML для выбранага запуску.

`--listen` прымае толькі loopback-адрасы, таму гэта лакальны інтэрфейс, а не сеткавы сэрвіс. Вынікі жывуць толькі ў памяці і знікаюць пры спыненні працэсу. Retention абмежаваны `--max-runs` (па змаўчанні `8`): завершаныя запускі могуць выдаляцца для вызвалення месца; `--max-concurrent` (па змаўчанні `1`) абмяжоўвае адначасовыя аналізы.

## Каманда analyze

```powershell
./techlog-stat.exe analyze `
  --input C:/v8/logs --glob "rphost_*/*.log" `
  --output C:/reports/overview --bucket 1m --workers 8 --top 100 `
  --format text,csv,json,html `
  --filter Usr=DefUser --filter DataBase=conf_null `
  --duration 500ms --date-from 2026-08-23 --date-to 2026-08-23 `
  --time-from 09:00 --time-to 18:00
```

| Параметр | Прызначэнне |
| --- | --- |
| `--glob` | Маска адносна `--input`; па змаўчанні `*/*.log`. |
| `--bucket` | Часавы інтэрвал для `analyze`; па змаўчанні `1m`. |
| `--top` | Колькасць самых працяглых зыходных падзей. |
| `--workers` | Максімальны паралелізм разбору файлаў. |
| `--filter key=value` | Дакладнае супадзенне поля; паўтарэнне аб'ядноўвае ўмовы праз AND. |
| `--duration` | Мінімальная працягласць; лік без адзінкі азначае секунды. |
| `--date-from` / `--date-to` | Уключальны дыяпазон `YYYY-MM-DD`. |
| `--time-from` / `--time-to` | Час сутак `HH:MM[:SS]`, у тым ліку інтэрвал праз поўнач. |

Метрыкі якасці разбору лічаць усе распазнаныя падзеі, у тым ліку выключаныя фільтрамі. Аналітычныя раздзелы змяшчаюць толькі запісы, якія прайшлі фільтр.

## Вынікі analyze

Запісваюцца толькі файлы выбраных фарматаў; `errors.log` ствараецца пры кожным запуску.

| Файл | Змесціва |
| --- | --- |
| `summary.txt` | Totals, тыпы падзей, абмежаваны Top SQL і якасць трас. |
| `event_types.csv` | Агрэгат для кожнага імя падзеі. |
| `sql.csv` | SQL/SDBL fingerprint, працягласць, радкі, кантэксты, карыстальнікі і базы. |
| `traces.csv` | Span трас з ідэнтыфікатарамі, палямі і зыходным тэкстам. |
| `locks.csv` | Агрэгаты блакіровак, канфлікты, сувязі і samples. |
| `scall.csv` | Групы SCALL і абмежаваныя прыклады. |
| `web.csv` | Агрэгаты і прыклады VRS-запытаў/адказаў/cache. |
| `sessions.csv` | Завершаныя і няпоўныя жыццевыя цыклы SESN/CONN. |
| `processes.csv` | Агрэгаты PROC/SCOM, яўныя сувязі і абмежаваныя прыклады. |
| `licenses.csv` | Агрэгаты LIC/HASP, бяспечная зводка сістэмы і рэдагаваныя прыклады. |
| `filedb.csv` | Агрэгаты DBV8DBEng і рэдагаваныя прыклады файлавай базы. |
| `error_contexts.csv` | Групы EXCP/QERR і прыклады супастаўленых/несупастаўленых EXCPCNTX. |
| `run.json` | Поўны `OverviewResult`, у тым ліку новыя раздзелы і іх лічыльнікі якасці. |
| `report.html` | Аўтаномны dashboard без CDN з абмежаванымі панэлямі даступных раздзелаў. |
| `errors.log` | Памылкі discovery або разбору асобных файлаў. |

HTML можна адкрыць непасрэдна з дыска. Справаздача ўключае часавы графік, навігацыю, пошук, сартаванне табліц, пераключальнік `(unknown)` і дэталі трас і блакіровак.

## Каманда compare

Спачатку стварыце два `run.json` праз `analyze`, затым выканайце:

```powershell
./techlog-stat.exe compare `
  --baseline C:/reports/before/run.json `
  --current C:/reports/after/run.json `
  --output C:/reports/compare `
  --threshold-pct 5 --threshold-abs-us 1000 `
  --format text,csv,json,html
```

`compare` супастаўляе totals, тыпы падзей, карыстальнікаў, базы, працэсы, SQL fingerprints, SCALL `ByCall`, web requests, SESN/CONN `ByEvent`, `PROCByProcess`, `SCOMByOperation`, `LIC` і DBV8DBEng `ByFunc`. Групы `EXCPCNTX` таксама параўноўваюцца, але толькі па count: яны не ствараюць класіфікацыю рэгрэсіі прадукцыйнасці.

Вынікі: `summary.txt`, `compare.csv`, `run.json` і `report.html`. Спецыялізаваныя радкі ўключаюць SCALL `ByCall`, web requests, SESN/CONN `ByEvent`, `PROCByProcess`, `SCOMByOperation`, `LIC`, групы EXCPCNTX і DBV8DBEng `ByFunc`, разам з overview і SQL. Радкі EXCPCNTX параўноўваюць толькі count: рост з'яўляецца падставай для расследавання, але не вынікам пра рэгрэсію прадукцыйнасці.

## Сумяшчальнасць

Каманды `sdbl-context`, `call-context`, database-, lock-, timeout-, deadlock- і error-description справаздач захаваны. Aggregate-рэжым запісвае summary, спецыялізаваны CSV, JSON і `errors.log`; `--mode raw` запісвае top N падзей кожнай гадзіны.

## Абмежаванні

- Імя файла павінна пачынацца з `YYMMDDHH`.
- `--filter` выконвае дакладнае радковае параўнанне, а не regex або пошук падрадка.
- Нармалізацыя SQL замяняе лікі і радковыя літэралы, але не аналізуе план выканання.
- Карэляцыя трас выкарыстоўвае source, process, OS thread і даступныя client/call/transaction identifiers. Сувязі VRS і кантэксту памылак патрабуюць адзінага сумяшчальнага кандыдата; неадназначныя запісы не звязваюцца па здагадцы. Метрыкі якасці паказваюць orphan, неадназначнасць і ціск лімітаў.
- Трасы, жыццевыя цыклы, web, кантэксты памылак, блакіроўкі і прыклады для расследавання маюць абмежаванае захоўванне. HTML-preview не трэба лічыць поўным.
- Утыліта аналізуе файлы падчас запуску і не з'яўляецца фонавым маніторынгам.
