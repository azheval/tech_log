# techlog-stat v1

## Контракт CLI

```text
techlog-stat <report> --input <dir> --glob <pattern> --output <dir> [--top N] [--format list] [--workers N] [--filter key=value] [--duration value]
```

## Флаги

- `--input`
  Корневой каталог для поиска логов.
- `--glob`
  Маска файлов относительно `--input`, например `*/*.log` или `rphost_*/*.*`.
  Поддерживаются wildcard-символы `*` и `?`.
  Разделитель пути внутри шаблона должен быть `/`.
  Рекурсивный `**` не поддерживается.
- `--output`
  Каталог результата одного запуска.
- `--top`
  Максимальное число строк в ранжированном выводе, по умолчанию `100`.
- `--format`
  Форматы через запятую: `text`, `csv`, `json`.
- `--workers`
  Параллелизм на уровне файлов, по умолчанию `1`.
- `--filter`
  Фильтр по сырому событию в форме `key=value`.
  Флаг можно повторять.
  Все фильтры объединяются через `AND`.
  Отсутствующее поле не вызывает ошибку, но событие не совпадает.
- `--duration`
  Минимальный порог длительности исходного события.
  Фильтр применяется до агрегации.
  1С хранит длительность в микросекундах, но CLI принимает удобный порог.
  Голое число трактуется как секунды: `--duration 5` эквивалентно `5s`.
  Поддерживаются суффиксы `us`, `ms`, `s`, `m`.

## Контракт Выходных Файлов

Каждый запуск создает отдельный каталог результата:

```text
<output>/
  summary.txt
  contexts.csv или errors.csv
  run.json
  errors.log
```

## summary.txt

Человекочитаемый отчет содержит:

- имя отчета
- временные метки генерации
- входные параметры
- счетчики файлов
- общее количество событий
- общую длительность
- среднюю длительность
- ранжированные строки

## CSV-Вывод

Контекстные отчеты пишут `contexts.csv`:

```text
rank,context,short_context,total_duration_ms,time_pct,count,count_pct,avg_duration_ms
```

Отчеты по ошибкам пишут `errors.csv`:

```text
rank,event,description,short_description,total_duration_ms,time_pct,count,count_pct,avg_duration_ms
```

## run.json

Метаданные выполнения включают:

- версию утилиты
- тип отчета
- временные метки
- длительность запуска
- входные и выходные пути
- счетчики файлов
- объем прочитанных данных
- выбранные параметры

## errors.log

Ошибки отдельных файлов и аномалии парсинга, которые не останавливают весь запуск.
