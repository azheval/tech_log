# techlog-stat v2

`techlog-stat` читает технологический журнал 1С и создает автономные отчеты. Во второй версии появились единый анализ `analyze` за один проход и сравнение периодов `compare`.

## Архитектура

```text
подходящие файлы
  -> потоковый parser internal/techlog
  -> упорядоченный обработчик событий
       -> общие агрегаты и временные bucket
       -> SQL/SDBL fingerprint
       -> трассы CALL/SCALL и контекст ошибок
       -> агрегаты и samples блокировок
       -> web, жизненные циклы, процессы, лицензии и файловая база
  -> text / CSV / JSON / автономный HTML
```

Файлы могут разбираться параллельно через `--workers`, но stateful-анализаторы получают события в порядке discovery. Фильтр применяется к событию до всех коллекторов: totals, SQL, трассы и блокировки всегда относятся к одной и той же выборке.

Parser и коллекторы работают за один проход. Разбор файлов может идти параллельно, но упорядоченный обработчик получает ограниченные batch и сохраняет детерминированную stateful-корреляцию. Примеры для расследования, состояние трасс, ожидающие контексты ошибок и HTML-preview ограничены.

## Покрытие событий и консервативная корреляция

Помимо overview, SQL, блокировок и трасс CALL, `analyze` формирует отдельные разделы:

| События | Анализ |
| --- | --- |
| `SCALL` | Серверные вызовы по `Interface`, `IName`, `Method`, контексту, пользователю, базе и процессу; длительности, доступные ресурсные метрики и ограниченные медленные примеры. |
| `VRSREQUEST`, `VRSRESPONSE`, `VRSCACHE` | Web-запросы/ответы, нормализованный URI, статус/результат, байты, cache hit/miss и ограниченные медленные/ошибочные примеры. Ответ или cache-событие связывается только с единственным совместимым кандидатом в lane source/process/thread при отсутствии конфликтов идентификаторов. |
| `SESN`, `CONN` | Только явные пары start/open и finish/close с явным ID. Attach-подобные записи и записи без ID не создают предполагаемый жизненный цикл. |
| `PROC`, `SCOM` | Агрегаты процесса и SCOM, ограниченные медленные PROC-примеры и только явно распознанные SCOM-связи процессов. |
| `LIC`, `HASP` | Классы получения/возврата/ошибок лицензии, источник HASP и безопасная сводка ОС. В примерах редактируются пути лицензий, серийные значения и MAC-адреса. |
| `EXCPCNTX`, `EXCP`, `QERR` | Группы ошибок и ограниченные исходные ошибки/контексты. `EXCPCNTX` обогащает только одну ближайшую совместимую ошибку в окне корреляции; неоднозначные и несопоставленные контексты остаются в метриках качества. |
| `DBV8DBEng` | Агрегаты файловой базы по функции, таблице, категории, файлу, базе, процессу, пользователю и консервативному классу операции. `Rows` и `RowsAffected` различают отсутствие и ноль; абсолютные пути файлов редактируются. |

Нормализация URI удаляет значения query, сортирует имена параметров и заменяет числовые или UUID-подобные сегменты пути. Это делает группы устойчивее и снижает случайное раскрытие данных, но не является границей безопасности для произвольного raw-события.

## Команды

## Локальный web-интерфейс: `serve`

Запустите встроенный локальный frontend с разрешенным root журналов:

```powershell
./techlog-stat.exe serve --input C:/v8/logs --listen 127.0.0.1:8080
```

Frontend автономен, встроен в исполняемый файл и не использует CDN или внешние assets. Он запускает анализ, показывает status и progress и позволяет запросить отмену. Для запуска выбирают каталог только в пределах root `--input` и glob относительно этого каталога, а также параметры анализа и фильтры.

Вкладки «Обзор», «События», SQL, «Трассы», «Блокировки» и «Исходные» поддерживают фильтрацию и drill-down к исходным событиям. Drill-down перечитывает только неизменяемый набор файлов, matched данным запуском, и никогда не использует путь или glob от браузера. UI сравнивает любые два завершенных in-memory запуска и формирует downloads CSV, JSON и автономного HTML для выбранного запуска.

`--listen` принимает только loopback-адреса, поэтому это локальный интерфейс, а не сетевой сервис. Результаты живут только в памяти и теряются при остановке процесса. Retention ограничен `--max-runs` (по умолчанию `8`): завершенные запуски могут удаляться для освобождения места; `--max-concurrent` (по умолчанию `1`) ограничивает одновременные анализы.

### Analyze

```bash
./techlog-stat.exe analyze \
  --input C:/v8/logs --glob "rphost_*/*.log" \
  --output C:/reports/overview --bucket 1m --workers 8 --top 100 \
  --format text,csv,json,html \
  --filter Usr=DefUser --filter DataBase=conf_null \
  --duration 500ms --date-from 2026-08-23 --date-to 2026-08-23 \
  --time-from 09:00 --time-to 18:00
```

| Параметр | Назначение |
| --- | --- |
| `--glob` | Маска относительно `--input`; по умолчанию `*/*.log`. |
| `--bucket` | Временной интервал для `analyze`; по умолчанию `1m`. Поддерживается синтаксис Go duration: `5m`, `1h`. |
| `--top` | Количество самых долгих исходных событий в overview; по умолчанию `100`. |
| `--workers` | Максимальный параллелизм разбора файлов; по умолчанию `1`. |
| `--filter key=value` | Точное совпадение поля; повторение объединяет условия через AND. |
| `--duration` | Минимальная длительность. Число без единицы означает секунды; допустимы `500ms`, `5s`. |
| `--date-from` / `--date-to` | Включительный диапазон `YYYY-MM-DD`. |
| `--time-from` / `--time-to` | Время суток `HH:MM[:SS]`; поддерживается интервал через полночь. |

Метрики качества разбора считают все распознанные события, в том числе исключенные фильтрами. Все аналитические разделы содержат только прошедшие фильтр записи.

### Compare

Сначала создайте два `run.json` командой `analyze`, затем выполните:

```bash
./techlog-stat.exe compare \
  --baseline C:/reports/before/run.json \
  --current C:/reports/after/run.json \
  --output C:/reports/compare \
  --threshold-pct 5 --threshold-abs-us 1000 \
  --format text,csv,json,html
```

`--threshold-pct` по умолчанию равен `5`, `--threshold-abs-us` — `0`. Сравнение охватывает totals, типы событий, пользователей, базы, процессы, SQL fingerprint, SCALL `ByCall`, web requests, SESN/CONN `ByEvent`, `PROCByProcess`, `SCOMByOperation`, `LIC` и DBV8DBEng `ByFunc`. Группы `EXCPCNTX` также сравниваются, но только по count: они не создают классификацию регрессии производительности.

## Результаты analyze

Записываются только файлы, выбранные в `--format`; `errors.log` создается всегда.

| Файл | Формат | Содержимое |
| --- | --- | --- |
| `summary.txt` | text | Totals, типы событий, ограниченный Top SQL и качество трасс. |
| `event_types.csv` | CSV | Один агрегат на имя события технологического журнала. |
| `sql.csv` | CSV | SQL/SDBL fingerprint без литералов, длительности, строки, контексты, пользователи и базы. |
| `traces.csv` | CSV | Одна строка на span трассы с идентификаторами, полями и исходным текстом. |
| `locks.csv` | CSV | Агрегаты блокировок по типу/контексту/таблице/региону, конфликты, связи и samples. |
| `scall.csv` | CSV | Группы SCALL и ограниченные примеры. |
| `web.csv` | CSV | Агрегаты и примеры VRS-запросов/ответов/cache. |
| `sessions.csv` | CSV | Завершенные и неполные жизненные циклы SESN/CONN. |
| `processes.csv` | CSV | Агрегаты PROC/SCOM, явные связи и ограниченные примеры. |
| `licenses.csv` | CSV | Агрегаты LIC/HASP, безопасная сводка системы и редактированные примеры. |
| `filedb.csv` | CSV | Агрегаты DBV8DBEng и редактированные примеры файловой базы. |
| `error_contexts.csv` | CSV | Группы EXCP/QERR и примеры сопоставленных/несопоставленных EXCPCNTX. |
| `run.json` | JSON | Полный `OverviewResult`, включая новые разделы и их счетчики качества. |
| `report.html` | HTML | Автономный dashboard без CDN с ограниченными панелями доступных разделов. |
| `errors.log` | text | Ошибки discovery или разбора отдельных файлов. |

CSV содержит UTF-8 BOM для совместимости с табличными редакторами. Длительности в overview JSON и аналитических колонках overview CSV указаны в микросекундах, если имя колонки не говорит иное.

### HTML dashboard

HTML можно открыть прямо с диска. В нем есть canvas-график временного ряда, навигация между разделами, поиск и сортировка таблиц, переключатель `(unknown)`, раскрываемые детали трасс/блокировок и локальное сохранение выбранной вкладки и простых UI-фильтров в браузере.

Чтобы не перегружать браузер, HTML показывает не более 100 SQL-строк, 100 трасс, 100 span на трассу, 100 строк блокировок на раздел и 4 000 символов исходного события. Полный сохраненный набор доступен в JSON и CSV.

## Результаты compare

При выборе соответствующих форматов `compare` записывает `summary.txt`, `compare.csv`, `run.json` и `report.html`. Специализированные строки включают SCALL `ByCall`, web requests, SESN/CONN `ByEvent`, `PROCByProcess`, `SCOMByOperation`, `LIC`, группы EXCPCNTX и DBV8DBEng `ByFunc`, наряду с overview и SQL. Строки EXCPCNTX сравнивают только count: рост является поводом для расследования, но не результатом о регрессии производительности.

## Существующие команды

Команды `sdbl-context`, `call-context`, database-, lock-, timeout-, deadlock- и error-description отчетов сохранены. Aggregate-режим записывает summary, специализированный CSV, JSON и `errors.log`; `--mode raw` записывает top N событий каждого часа.

## Ограничения и интерпретация

- Имя файла должно начинаться с `YYMMDDHH`; ошибочное имя попадает в диагностику отдельного файла и не останавливает запуск.
- `--filter` — точное строковое сравнение, а не regex и не поиск подстроки.
- Нормализация SQL заменяет числа и строковые литералы. Это fingerprinting, а не SQL parser и не анализ плана выполнения.
- Корреляция трасс использует source, process, OS thread и при наличии client/call/transaction identifiers. Связи VRS и контекста ошибок требуют единственного совместимого кандидата; неоднозначные записи не связываются по догадке. Метрики качества показывают orphan, неоднозначность и давление лимитов.
- Трассы, жизненные циклы, web, контексты ошибок, блокировки и примеры для расследования используют ограниченное хранение. HTML-preview не следует считать полным.
- Утилита анализирует файлы, доступные во время запуска. Это не фоновый мониторинг и не система alerting.
